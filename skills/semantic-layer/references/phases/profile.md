# Phase card: profile

Load this card when `sl next` names phase `profile`. It holds measuring the in-scope tables and keeping protected columns to counts. Load `references/intake.md` (The query-plan protocol) only when the source is a warehouse dialect run through your own SQL tool.

**Checklist:** 1. `sl profile --source <s>` (a batch: `--tables a,b,c`). 2. `sl tables --source <s>` shows the profile state. 3. `sl validate`.

```
sl profile --source <s>
```

Profiles in-scope tables only. `sl tables` shows each table's profile as `yes`, `partial` (some columns profiled, but new or retyped ones not) or `no` (`profile_state` in `--json`); `sl status` counts only `yes` as profiled, and `sl profile` profiles the other two alike. On a large source, profile one batch at a time with `--tables a,b,c`; use `--refresh` after the data changed. A table the database refuses (no SELECT permission, a timeout) is skipped with its reason and the rest are saved; `sl next` then offers the retry, or the grant to ask the owner for, and a rerun profiles only the tables still missing or skipped (`--all` profiles every one again). For warehouse dialects use `--emit-sql` and `--results` as in intake, and set `profile.sample_rows` in the source file when full scans are slow or costly (a write without a typed command: `SKILL.md`, Hand edits). A protected column (tagged `pii` or `sensitive`, in `ignored_columns`, or personal or sensitive by name or by being near-unique text) keeps counts only: its null fraction and distinct count, and a min and max only for numbers and dates; its top values are not stored, not even hashed. The name rules are a heuristic: tell the owner to review `snapshots/` before committing them and to name any personal column the rules missed, then tag it; after tagging a column already profiled, run `sl profile --source <s> --redact` (`sl validate` warns until then), which also removes the hashed values an older snapshot holds. With `profile.sample_rows`, Postgres and BigQuery sample a table with a row estimate with `TABLESAMPLE SYSTEM` (a view sorts every row instead), and one query reads a table's sample for every column's top values. A BigQuery profile prints a cost warning first: run each plan query with `bq query --dry_run` to see the bytes it scans, and tell the owner the total before running them.
