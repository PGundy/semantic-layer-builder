# Phase card: intake

Load this card when `sl next` names phase `add-source`, `introspect` or `connect`, when there is no `semantic.yaml` yet, or when the owner adds a source. It holds the first turn, intake per source, the export fallback and its upgrade, and the baseline that follows intake. Load `references/intake.md` for details, dialect notes, lake discovery, the export per database and the shared-context formats.

## First turn

**No `semantic.yaml` yet.** Unless the owner has already named a source's connection (a variable name, a lake folder), your first message asks for a read-only connection to each source, with one plain sentence of why (Connection first, below), before anything about an export. Do the setup in the turn that has the connection, or the owner's answer that none is possible, before asking any scoping question: propose a default project name from the company or the source (`acme`) and run `sl setup --source <s> --dialect <d> --env <VAR> --name <default>` (Intake, below) for every source the owner has connected, which runs `sl init --name <default>`, then writes the source as `sl add-source` would and reads it as `sl introspect` would; for a source whose connection is not possible, the export path below. Then `sl baseline` for each source that now has a snapshot (After intake). Then send one message that opens with the baseline's short plain-English version ("here is what I think your tables are; correct me"), says that the project name can be changed by editing `name` in `semantic.yaml`, asks for the name to record as the approver (`--by "Dana Ruiz"`, used for every approval in the session), and opens scoping (`phases/scope.md`).

## Intake, per source

**Checklist:** 1. Ask for a read-only connection first, with its reason. 2. `sl setup --source <s> --dialect <d> --env <VAR> --schemas a,b` per source (live), `sl introspect --emit-sql` then `--results` (warehouses), or, only once the owner says a connection is not possible, `sl export-sql` then `sl setup --export <file> --reason "<why>"`. 3. `sl validate`.

Ask what data they have: databases, warehouses, folders of files, a dbt project. Each one becomes a source. Register each source separately (a warehouse, a lake of Parquet files, an events database) and run intake, scoping, profiling, drafting, the interview and the joins per source: scope, profile and interview each one on its own. For a lake of files, one DuckDB source with a view per dataset, likely noise included, keeps scoping and profiling the same as a database.

**Connection first.** Ask for a read-only connection to each source before anything else, with one plain sentence of why: profiles, join evidence and goldens need the data (which values exist, which keys are unique, how tables join, whether a figure matches one the owner trusts), table definitions alone cannot show them, and the role only reads. The owner sets the variable; never ask for its value. With a connection, one command registers the source, reads its catalog limited to the schemas and previews the scope (`references/intake.md`, One step):

```
sl setup --source warehouse --dialect postgres --env WAREHOUSE_URL --schemas acme,marts --include "fct_*" --include "dim_*"
sl setup --source lake --dialect duckdb --view "web_events=read_parquet('../data/web_events/*.parquet')"
```

When the owner has no suitable credential, `sl setup --print-role-sql --dialect <d> --schemas a,b` prints the statements for a least-privilege, read-only role on those schemas. Hand them to the owner for their database administrator to run; never run them for them. On connect the CLI reports what the role can do: pass any warning it prints (a superuser, write privileges, schemas beyond `intake.schemas`) to the owner in plain words and suggest that role.

**When a connection is not possible.** Offer the schema export only after the owner says so, and record why in their words: `sl setup --source <s> --dialect <d> --export <file> --reason "<why>"` writes it to `intake.reason`, and you add it to the source's `description`. An export source may approve definitions with the owner, but profiles, join evidence, goldens and drift from data wait on a connection: no golden can be confirmed (`sl goldens run` and `confirm` refuse), an approved join warns until its evidence exists, and `sl status` never reports `done` (its last phase is `connect`). `sl status` names the upgrade on every session start (`next_step.connection_upgrade`), and `sl next` names it (kind `run`) as the `connect` step once every other step is done; at each session start ask the owner once whether a connection is possible now. With one, `sl setup --source <s> --dialect <d> --env <VAR>` (duckdb: `--database <path>` or `--view`) upgrades the source in place, keeping every answer and approval: it profiles, checks every join and lists the items the data contradicts, and its next step reads them back (`sl readback --targets <refs>`) for the owner to answer (`references/intake.md`, Upgrade).

Then capture its tables by one of four paths.

- **Live** (duckdb, postgres): `sl setup` reads it; `sl introspect --source <s>` reads it again.
- **The agent's own SQL tool** (snowflake, bigquery, databricks, or any source the CLI cannot reach): `sl introspect --source <s> --emit-sql`, run each query with your warehouse connector or CLI, save `{"<id>": [rows]}`, then `sl introspect --source <s> --results <file>`. BigQuery: ask which datasets matter first and add `--schemas <dataset>,<dataset>`.
- **Schema export** (only after the owner says a connection is not possible): `sl export-sql --dialect <d> [--schemas a,b] [--include <p>]... [--exclude <p>]...` prints the read-only catalog query for their database (postgres, redshift, mysql, sqlserver, snowflake, bigquery, databricks, duckdb; `references/exports/<d>.sql`) and, on stderr, how to run it and save CSV. `--include` and `--exclude` take the scope patterns of `phases/scope.md` and are written into the query, so the export lists only those tables; a pattern the dialect's SQL cannot hold is applied by `sl import` instead, as the query's header says. Give the owner the query and that line; it reads only the catalog, never table data. Then `sl setup --source <s> --dialect <d> --export <the saved file> --reason "<why>"` (`schema.csv`, or `schema.tsv` from MySQL) imports it; `sl import --source <s> --file <file>` reads a fresh export later. A Redshift, MySQL or SQL Server source is registered as `postgres` (`references/intake.md`); for MySQL and SQL Server only the export and the baseline are supported, since every expression the layer writes is Postgres SQL that no tool may run on their database as is.
- **Other shared context** (a dbt project, DDL, an older export): `sl import --source <s> --file <path>`. The format is detected from the file (`.sql` is DDL, a JSON object with `nodes` a dbt manifest, a CSV or JSON array an information_schema export); `--format information_schema|dbt_manifest|ddl` overrides.

Rerunning `sl introspect` or `sl import` on a source that already has a snapshot prints what changed (`phases/drift.md`).

For a lake folder whose datasets you do not know yet, list its files with your own file tools or ask the owner for the listing (a duckdb source without views has no file access; see `references/intake.md`). Make one view per dataset, likely noise included, so scoping can flag it. To add or change a view later, rerun `sl setup --source <s> --dialect duckdb` with a `--view name=relation` for every view the source keeps, old and new (`--view` replaces `connection.views`, editing `sources/<s>.yaml` in place), which reads the catalog again; `sl validate` errors on a credential there. Each view is one table expression (`read_parquet(...)`, `read_csv(...)`, `iceberg_scan(...)` or a table name), never a subquery, and `connection.setup` holds only `INSTALL` or `LOAD` of a named core extension, `SET` of a known safe setting and `CREATE SECRET` from a provider chain or the environment; `sl validate` errors on anything else and the adapter refuses it (`references/intake.md`). Views have no row count until `sl profile` measures them, and an in-memory source's views are in schema `main` (`main.web_events`; `web_*` matches the view name).

## After intake: the baseline

**Checklist:** 1. `sl baseline --source <s> --json`. 2. Open with its plain-English version. 3. Scope first when it left tables out.

```
sl baseline --source <s>
```

Read-only, from the snapshot alone; profiles and existing models sharpen it. Load `references/baseline.md`. For the in-scope tables (the top `focus_threshold` when there are more, with a note naming how many it left out) it guesses each table's role (fact, dimension, bridge, event, snapshot, staging, noise) with its reasons, what one row is, keys, relationships with fan-out warnings, candidate measures, candidate splits (time columns, low-cardinality columns, attributes of joined dimensions such as `customer.acquisition_channel`), columns that should not be splits, and the questions for the owner in order of importance; a source-level star-schema sketch lists which dimensions each fact joins. Use `--json` to read it; plain output is markdown for the owner, and `--out <file>` writes it under the semantic root.

Open the conversation with a short plain-English version of it ("here is what I think your tables are; correct me"), every heuristic worded as a guess with its reason, never as fact, within Principle 6's limits. Then let it drive the session: its noise and staging tables and its left-out note frame scoping (`phases/scope.md`); its grain, key and relationship guesses are the table-structure questions (`phases/interview.md`); its candidate measures are the menu for metric definitions (`phases/interview.md` and `phases/metrics.md`); its candidate splits become dimensions. Without profiles it says which facts `sl profile` would measure; rerun it after profiling. When the brief has a left-out note, or more tables are in scope than `focus_threshold`, scope first (`phases/scope.md`) and ignore its closing `sl profile` and `sl draft` hint until the scope is written: that hint lists every unprofiled table it covered, staging ones included, and `sl draft` refuses until the source is focused. Nothing in it stands until the owner confirms it in a readback.
